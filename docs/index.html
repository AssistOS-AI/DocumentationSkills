Repository overview

DocumentationSkills Documentation

DocumentationSkills is a reusable catalog of self-contained instruction bundles and supporting utilities for maintaining technical documentation as an implementation-backed contract. Consumers copy the skill folders they need and retain each skill’s local references, examples, scripts, and assets.

The design specifications are the source of truth for repository structure and skill contracts. Start with the specification matrix and use DS001-coding-style.md for source layout and test organization.

Catalog structure

The repository root owns catalog guidance and documentation. Each directory under skills/ owns its operational descriptor and any supporting references, examples, scripts, or assets. A consuming project copies the complete selected folder so that skill-local assumptions remain visible and auditable.

Runtime and validation

Node.js is used by executable examples and documentation utilities. Most skills are instruction bundles; article-build and gamp-specs also carry executable modules or verification scripts.

Executable modules and scripts should be checked with focused Node.js syntax or fixture-based tests in the consuming project. DocumentationSkills does not define a repository-wide test runner.

Documentation maintenance

AGENTS.md defines the mandatory reading order. The HTML pages explain operational behavior, while files under docs/specs/ define durable constraints. When a descriptor, script, example, dependency, or output changes, update the corresponding HTML page and DS file in the same revision, regenerate docs/specs/matrix.md, and verify local links.
