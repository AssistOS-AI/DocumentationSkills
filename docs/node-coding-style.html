Skill reference

Node Coding Style

Supplies a default coding style for projects and portable skills when it is available and no explicit user or project instruction selects another approach. Generated executable code uses Node.js ECMAScript modules in .mjs files, async/await, built-ins, and local resources. Explicit language or framework choices remain authoritative within their scope.

Default behavior

The agent reads project guidance and the relevant code before applying the default. It records the effective rules when project guidance is initialized or updated as part of the task. Existing public interfaces remain intact, and unrelated legacy files are not automatically renamed or rewritten. The consuming agent must discover and follow the descriptor; copying a folder alone does not configure every agent runner.

Dependency exceptions

The skill prefers eliminating dependencies or using a small implementation based on Node.js built-ins. When no suitable equivalent meets the requirement, Python, an external library, or a CLI tool may be justified. Small standalone components with few or no transitive requirements are preferred. Accepted source is pinned and preferably retained under the project's or owning skill's external/ folder with its licenses, notices, assets, and local changes.

The project or skill keeps dependencies.md even when no external dependency exists. Each accepted direct or transitive dependency records its purpose, version, location, required or optional scope, acceptance reason, rejected alternatives, authorization, source and update URLs, exact license obligations, local changes, startup check, installation steps, and removal opportunity. Vendored code and already installed tools remain dependencies. MIT and Apache-2.0 are preferred; LGPL is an exceptional limited-copyleft choice whose actual obligations must be documented.

Python and environment prerequisites

Discovery of executable Python skills triggers one question about conversion unless the project or session already settles that decision. An accepted conversion preserves interfaces and outputs and removes obsolete Python requirements only after validating behavior and checking remaining consumers.

An unavoidable heavy dependency may be installed in the environment with user authorization. Required dependencies are checked before application or affected skill-script work. Missing or incompatible prerequisites produce actionable stderr errors and a nonzero exit before side effects. Optional dependencies are checked when their feature is selected. Startup never installs dependencies.

Local artifacts and integration

  • SKILL.md defines the operational rules; DS.md summarizes the portable contract.
  • dependencies.md declares that this instruction-only skill has no runtime or third-party dependencies.
  • assets/dependencies.md supplies the dependency record template for consuming projects and skills.

The complete folder is the installation unit. GAMP Specs incorporates this default when available without requiring the style skill as a dependency. Consumer documentation describes the host project's effective rules; skill-specific material remains inside the copied skill folder.
