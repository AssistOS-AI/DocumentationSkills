Overview

Wiki

These terms describe the project's own components and contracts.

Skill bundle

A skill bundle is one directory under skills/ containing a SKILL.md descriptor and any local resources it references. Consumers copy the complete directory so that scripts, examples, templates, and reference files remain available. The catalog does not make one imported skill a hidden runtime dependency of another.

Design specification

A design specification states a product requirement, invariant, rationale, or boundary in declarative form. Files beneath docs/specs/ have stable identifiers and exact-stem title metadata. The matrix and specification viewer provide navigation; explanatory HTML describes the same verified contract for readers.

achilles-specs

This integration skill describes how a consuming project resolves AchillesAgentLib, configures model tiers, and uses LLMAgent. It extends project setup requirements rather than implementing another model gateway. A consumer must keep its confirmed runtime and credential boundaries.

article-build

This skill combines an instruction contract with Node modules for research articles. The article root owns its plan, bibliography records, chapter inputs, and assets; the builder writes rendered HTML and a build manifest. It uses dependency changes to limit rebuilding and checks citation evidence and SVG geometry before accepting outputs.

detect-main-behaviors

This analysis skill identifies the user outcomes, essential paths, and major hidden mechanisms that define a project. It accepts or rejects candidates using source and test evidence and returns ordered components. It does not edit specifications or promote an unsupported feature into the product contract.

gamp-specs

This authoring skill synchronizes onboarding, guidance, HTML pages, and design specifications with implementation evidence. Its helpers generate the two-column specification matrix, check local documentation links, and verify static resources over HTTP. It uses an accepted main-behavior handoff and preserves explicit project choices.

node-coding-style

This instruction skill supplies default Node.js ECMAScript-module and dependency rules when a consuming project has no explicit override. It requires justified dependency records and portable resource ownership. Existing language choices remain authoritative within their scope, and converting existing Python skills requires authorization.

review-specs

This review skill audits documentation format, navigation, reading order, terminology, and supported meaning. It returns evidence-based findings and remediation directions without modifying any file. Correct and understandable content is preserved instead of being rewritten to express a preference.

human-report

This instruction skill defines the human-readable portion of an execution response. Its markers delimit that report, while a workflow may require a separate technical payload in the same response. The consuming workflow determines how to retain or pass onward those two parts.

unslop

This editing skill removes formulaic or inflated language from documentation. It preserves the intended meaning and technical identifiers while replacing vague claims with concrete actors, actions, and results. It applies to writing and does not establish whether a technical claim is true.

web-design

This instruction skill addresses HTML and CSS interface decisions such as navigation, overlays, forms, spacing, and themes. It asks authors to inspect the rendered interface and preserve usable focus and layout behavior. Project-specific presentation requirements still govern the design.
