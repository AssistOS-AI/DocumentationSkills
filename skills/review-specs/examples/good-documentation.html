AchillesAgentLib Documentation

AchillesAgentLib is a JavaScript library for running language-model agents through declarative skills. It gives an application one runtime for discovering skills, selecting a model, executing a task, and preserving session context.

Applications use the shared runtime to discover skills, choose an executor, run tasks, and keep the context needed for multi-step work. The skill families section explains how reusable task instructions and execution code are packaged for different kinds of work.

A skill packages the instructions and task-specific code needed for a reusable operation. The library can register that skill once and run it through the appropriate subsystem whenever an application requests the operation.

How MainAgent runs a task

MainAgent is the main point of interaction with AchillesAgentLib. An application sends a task instruction to MainAgent, which discovers the registered skills, selects an enabled skill, and forwards the request to the subsystem responsible for that skill's descriptor type.

flowchart LR
                Caller --> MainAgent
                MainAgent --> Skill[Enabled skill]
                Skill --> Subsystem[Specialized subsystem]
                Subsystem --> LLMAgent
                LLMAgent --> Result[Task result]

The selected subsystem prepares the task, uses LLMAgent or another configured executor when needed, and returns the result to MainAgent. MainAgent then returns that result to the application. Disabled skills remain in the catalog for inspection but are excluded from execution and tool surfaces.

LLMAgent

LLMAgent is the shared interface used by subsystems to call configured language models. It handles provider invocation, response shaping, intent interpretation, and the memory associated with a task, user, or session.

Agentic sessions

MainAgent uses an agentic session when a task requires more than one model or tool action. An agentic session is a bounded sequence of those actions for one task. Its session state lets a later action use the earlier task context, while cancellation and retry controls keep the sequence recoverable and limited.

Skills and subsystems

A skill defines a reusable operation through task instructions and, when required, task-specific code. A subsystem is the runtime component that loads and executes one family of skill descriptors. This division lets the library support different inputs, preparation steps, and outputs for different task families.

Skill families

Skill families group reusable operations that need the same kind of task data and execution code. The family determines which subsystem prepares the request and what inputs and outputs the skill exposes.

Orchestration skills

Orchestration skills coordinate several bounded actions or other agents. They use loop or SOP sessions when a task needs multiple steps and can declare which remote Ploinky agents may participate.

DBTable skills

DBTable skills describe table fields and database operations in tskill.md. The DBTable subsystem reads that description, prepares field presenters and validators, and uses the resulting functions for create, update, select, or delete workflows.

Code skills

Code skills define executable modules and the arguments passed to them. The code-skill subsystem loads the declared entry module, invokes it through the agent runtime, and returns its result to the caller.
